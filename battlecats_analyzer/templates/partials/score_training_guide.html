{# 評分 / 數據訓練流程說明 — 陣容、卡池、詳情頁共用 #}
評分 / 數據是怎麼訓練來的？

組員在 本機 / Colab notebook 離線算好，匯出 CSV / JSON 後由網站讀檔顯示。 Render 上設 SKIP_ML_BUILD=true，不會在線上重新訓練任何模型。

① 原始資料（爬蟲）

  • 來源：DA_ML_期末專案/爬蟲/DA_ML_期末專案_爬蟲.ipynb 從 battlecats-db 抓取角色 JSON
  • 產物：battlecats_ALL_db.json（各階段面板、射程、速度、能力 ID 等）
  • 人工標籤：rated_data/score.csv — 組員對部分角色打 0–4.5 分，供 ML 監督學習

② 陣容三模組分（0–10）— 陣容評分用

  • Pipeline：battle_cats_ml_test3/features.py 抽特徵 → scoring.py 算三軌 raw 分 → min-max 縮放到 0–10
  • 模組1 面板白質：DPS、成本效率、射程、速度等加權（見 MODULE1_PANEL_WEIGHTS）
  • 模組2 屬性特化：對紅/黑/浮/天使等敵人特攻能力加總
  • 模組3 屬性控場：緩速、停止、波動等控場能力加總
  • 匯出：data/module_scores_export.csv → 網站 roster_analysis.py 對勾選角色取三模組平均
  • 另：ml_train.py 用 RandomForest（200 棵樹）對有人工標籤的角色做 Spearman 評估；主要用於驗證特徵，模組分本身以規則 + 特徵工程為主

③ 綜合評分（0–5）— 卡池 EV、角色星等用

  • Notebook：卡池預測/DA_ML_rare_model.ipynb
  • 模型：XGBoost，輸入模組1/2/3 分與清洗後 SSR/SSSR 特徵，預測 0–5 綜合分
  • 有人工標籤的角色保留「真實評分」；其餘填「預測評分」→ 合併成 綜合評分 欄
  • 匯出：data/battlecats_final_tier_list.csv → tier_list.py、卡池 EV 引擎

④ 卡池期望值 EV — 規則公式（非 ML 訓練）

  • 邏輯移植自 DA_ML_PoolScore.ipynb → gacha_explanation_engine.py
  • 假設：SSR 單抽 5% 均分池內 SSR 數；SSSR 0.3% 均分 SSSR 數
  • ev_initial = Σ(機率 × 綜合評分)；ev_current = 只加總尚未擁有角色的貢獻
  • 推薦門檻 PR40=0.1185、PR80=0.1366：對全部卡池、零持有 baseline 跑一遍 EV 後取 40% / 80% 分位數
  • 卡池成員清單：gacha_pool_characters_mapping.json（非爬蟲即時抓取）

⑤ 角色短評（文字）

  • id_review_sections_export.csv — 泛用性 / 戰術 / 培養建議，由組員整理或規則產生
  • 不參與 EV 數字計算，僅供卡池分析頁「角色短評」區塊

重新訓練後：覆蓋 battlecats_analyzer/data/ 對應 CSV → 本機測試 → push GitHub → Render 自動部署。 詳見 README「§4 資料怎麼從 ML 流到網站」。
